# Decisiones de la oficina

La misión de producto autorizada conserva su MD completo, sesión de Opus 5.5, clave y presupuesto. El propietario fijó un máximo de 10 Haiku 5.5 simultáneos globales, incluyendo revisores; tareas con archivos compartidos se serializan. Opus recupera fallos y corrige perfiles con revise_task, sin intervención de Codex en el producto. Los objetivos reducidos conservan el worktree anterior; read_file(taskId) permite recuperar resultados de la misma misión. Los límites de fixture descritos más abajo no sustituyen los límites de producto (40 turnos/30 minutos, 200 tareas, 48 pases del director).

Haiku implementa y revisa los scripts release:publish y release:verify:production. Opus integra una vez tras todos los requisitos y checks y llama publish_candidate, que ejecuta esos scripts bajo lock, verifica el commit limpio, la web existente y descarga pública de APK con SHA-256. El informe ignorado reports/release-publication.json incluye commit, version, minSdk, webUrl, apkUrl y sha256. Un script fallido o URL/hash incorrectos dejan la misión pendiente; DONE solo llega tras publicación verificada. Codex mantiene exclusivamente la oficina.

TypeScript, React 19.3, Vite 8.3.4, Node 24 y SQLite nativo. Anthropic Agent SDK 0.3.296 con runtime Windows 2.1.296 y Anthropic SDK 0.133.0. Versiones fijas y lockfile; dependencias opcionales del SDK conservadas. No instala Python, WSL, Docker, Rust ni Android. El runner es privado y no forma parte del build raíz Vercel.

`packages/contracts` valida entradas de misión, tareas e informes con Zod. `orchestration` contiene SQLite, migración 001, reservas transaccionales, leases, cola, política de rutas y cancelación. `anthropic-adapter` es la única frontera de ejecución de modelos. `telemetry` conserva tarifas verificadas; el SDK calcula las estimaciones operativas y los precios desconocidos quedan sin reconciliar. `git-integration` mantiene un único escritor. `office-scene` adapta el bucle Canvas MIT de Pixel Agents a nuestros eventos; los sprites son dibujos propios.

Opus recibe mapa QR, objetivo, aceptación y resultados agrupados. Crea tareas, encola, solicita revisiones y decide integrar. No tiene Bash/Write/Edit. Trabajadores son queries Haiku independientes. Revisores ocupan plazas, leen el worktree terminado y ejecutan checks. Los informes DONE necesitan evidencia y revisión; la integración vuelve a comprobar el conjunto. Las correcciones sucesivas se integran como snapshot neto frente a la base, conservando commits parciales.

MCP de coordinación: create_task, assign_task, inspect_task, submit_result, request_review, revise_task, request_integration, record_decision, pause_run, resume_run, cancel_run. Los trabajadores ven únicamente lectura, checks, informe y escritura en archivos asignados si su rol y misión la permiten. Director y revisión no reciben escritura ni shell. El servidor limita origen, Host, secreto de control y cuerpos JSON. Rutas relativas no aceptan traversal, ADS, rutas absolutas, `.git`, secretos ni enlaces fuera del worktree. Los comandos reciben ejecutable/args/cwd estructurados y un entorno sin credenciales API. Esto no es una sandbox del sistema operativo: las comprobaciones ejecutan código del proyecto autorizado.

SSE notifica eventos sin mostrar thinking ni un bloque por token. La UI limita historial visible, ofrece Canvas/lista equivalente, inspector, costes, pausa/cancelación/contexto, exportación JSON/CSV y configuración. Zoom/pan se guarda localmente, animación se reduce según la preferencia del sistema. Tiempos API acumulados de sesión se etiquetan aparte de la duración de query.

Presupuesto se reserva mediante BEGIN IMMEDIATE. Uso de mensajes se deduplica por sesión/message.id; cierres acumulan incrementos y snapshots por sesión/época. Result y modelUsage incluyen subagentes/auxiliares nativos; worker queries se contabilizan por separado. Reserva de un crash se conserva hasta reconciliación manual. Ningún saldo, promoción o renovación se infiere de la clave.

El SDK maneja hasta dos reintentos de errores transitorios con su política de Retry-After/backoff; la cola no vuelve a llamar automáticamente una query fallida. Autenticación, créditos y modelo inválido bloquean. Máximo 18 turnos y 5 minutos/query; checks 2 minutos; máximo 40 tareas y seis intervenciones del director por misión antes de pedir contexto. Todos los límites siguen sujetos a llamadas en vuelo y estimación de precios.

Superpowers se conserva íntegro en las carpetas seleccionadas. Se adapta su workflow: nuestras herramientas de coordinación sustituyen herramientas de otros hosts; paralelismo solo con worktrees, contratos y propiedad independiente; presupuesto, modelos y Git los controla Morphiq. No se instala la metodología global ni se aplica planificación de funciones nuevas al QR. No se afirma cumplimiento literal de workflows adaptados.

Mission Control alpha y ccusage se usan como referencias de contratos/medición; no arrancan otros schedulers ni representan saldo oficial. Ruflo, BMAD, claude-office, pixel-agents-standalone y ai-company quedan como alternativas de referencia, fuera del runtime inicial. Agent Teams experimental no se utiliza.
